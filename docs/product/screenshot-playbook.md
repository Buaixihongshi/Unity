## 一、尺寸与画面规格（v2 定死）

v1 同时写了“基准 1280×800”和“局部图按内容外扩 24–32px 裁切”，两条有冲突，导致第一批图出现三种尺寸。v2 只保留下面两种规格：

| 类别 | 适用图号 | 拍法 | 成品尺寸 |
| :--- | :--- | :--- | :--- |
| 会话页 | 0-1、1-2、1-3a、1-3b（以后补拍的 1-4 同样适用） | 浏览器视口 1280×800，像素比 1x，截整屏，靠滚动位置让目标内容进入画面，不再另外裁切 | **1280×800** |
| 设置页 | 0-2、1-1、1-5、1-6 | 同一视口打开设置弹窗，只截弹窗本体 | **1126×680**（1280×800 视口下设置弹窗的实际尺寸） |

- 拍摄前先确认视口和像素比，成品尺寸不符就重拍，不缩放凑尺寸。
- 统一使用浅色主题。
- 原图不加边框，也不画标注框。边框交给文档样式处理；如果确实需要标注，后期统一加，不在拍摄阶段做。
- 画面里不能出现完整的本机路径、凭据或私人数据。路径会露出来的页面，先调整视图避开；避不开就在成品上打码，并在清单里注明。
- 构图做一两次调整就够了。反复调滚动、字号和弹窗宽度不能让图变得更真实，只会把时间耗光。
- 只能用滚动、展开/收起原生控件来构图；不注入 CSS，不改字号、弹窗尺寸或页面缩放。画面要和用户在同一视口下看到的一致，一屏放不下就拆成两张。

## 二、图号与拍摄要求

| 图号 | 内容 | 要求 |
| :--- | :--- | :--- |
| 0-1 | 会话全貌（接力和产物卡片） | 左栏会话列表、张楚岚的发言、王也的接力回复、`reading-club-agenda.md` 产物卡片要在同一屏里 |
| 0-2 | 设置 → 扩展 | 三个扩展开关 |
| 1-1 | 设置 → 团队配置 | 三个角色分别使用不同的连接和模型。**以实际配置为准**，v1 写的“Claude 3.7 / GPT-4o”作废 |
| 1-2 | `/discuss` 综合稿 | 综合稿卡片和“团队需要你的选择”面板要在同一屏里 |
| 1-3a / 1-3b | 等待确认的任务提议弹窗 | 需要先开启任务扩展，必须是真实对话触发的，不用演示数据。原生弹窗在 1280×800 下放不下全部内容，拆两张：**1-3a** 弹窗顶部（提议标题、目标、负责人、本次范围）；**1-3b** 滚到底部（怎样算完成、“确认并开始”按钮）。“提议来源与版本”保持收起 |
| 1-4 | 超时后宿主留下的记录 | 先空着，遇到真实超时再按会话页规格补拍，不刻意制造超时 |
| 1-5 | 设置 → 观测 | 展开一次回合的详情，能看到模型、工具调用、耗时和用量 |
| 1-6 | 设置 → 记忆 | **改为拍保存后的列表态**（v1 要求拍编辑态，容易拍出计数和卡片对不上的画面）。等保存完成、计数刷新以后再拍，计数和卡片数量要一致；路径不露出 |

演示剧本仍然使用 v1 的“周末读书会精读《置身事内》”：会话 A 产出 0-1、1-2、1-3a、1-3b，设置页的图沿用同一份数据。

## 三、文件操作规则

- 成品只写进功能分支 worktree 的 `docs/product/images/`，不写进主 checkout。
- 临时图、试拍图放在 worktree 外的临时目录（例如 `/tmp/unity-shots/`）。
- 清理时只删除明确列出的文件名，**不在成品目录里用通配符删除**（见 Issue #125）。
- 每拍完一张，先更新 `docs/product/images/MANIFEST.md`，再做下一张。
- 只在功能分支自己的开发数据上拍摄，不碰日常实例。需要把会话退回到之前的状态才能拍时，动手前先在聊天室报出备份路径和还原方法；拍完按该方法还原，并报告还原后的核对结果（任务、提议和事件是否完整）。

## 四、执行节奏

一轮只做一件事，做完立刻在聊天室汇报结果（成功、卡住或失败都要报），然后再领下一件。不要在一轮里把多张图一起拍完。
