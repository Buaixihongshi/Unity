# 会话图片附件实现计划

需求与验收：用户可选择、粘贴、拖入静态图片；随新消息和插话发送、查看历史缩略图和当前页大图。单张 3,932,160 字节、单条 4 张、mission 累计 8 张 / base64 后 16,777,216 字节；动图明确拒绝。上传失败和提交拒绝保留草稿，不丢弃图片后重试模型。

实施顺序：私有附件存储、受限解码与原子绑定 → 各 CLI/API 输入及降级记录 → 输入框与消息显示 → 边界/并发/失败回归、真实 CLI 和包内 Pillow 自验 → 非作者审查和 PR。

存储独立于 artifacts，附件通过不可猜测 ID 与会话关联。消息绑定和 mission 预算在 SQLite 写事务内裁决；失败回滚整条提交。复用只限同会话最后用户消息的显式修订。旧消息的附件字段默认为空列表。CLI 每轮仅拿临时副本；API 图片只进入请求体，日志不记录像素。

恢复边界：不修改日常实例、不迁移生产数据、不合并或部署。未绑定附件在启动时清理超过 24 小时的记录；会话删除移除附件。新增数据兼容旧 JSON 消息；回退到旧代码不能展示图片，不能以回退操作清空附件。发布与状态恢复仍依照 RELEASING。

验证覆盖：上传类型/损坏/动图/尺寸/字节边界，4/8 张和编码后预算、并发重复绑定、跨会话、重复修订；CLI stdin/argv 与 API 三种协议；上传等待/失败/移除/切换会话和灯箱。真实路由和未完成验收必须分开写明，fixture 不替代真实验收。
